# Security review

Phase 7 review of what Archi-Made-Easy adds to the inherited product, against the scope set in [PLAN.md](PLAN.md) section 7: injection into the data slots, the message bridge, frame sandboxing and path handling, plus the exporters, the installer and network access. Reviewer: the implementing agent, reading the code and attacking it with tests. This is not an independent audit.

Date: 2026-11-10, extended 2026-11-11 with the release-readiness audit (S-08 to S-12). Tree: the 1.0.0 release candidate (see [RELEASE-ACCEPTANCE.md](RELEASE-ACCEPTANCE.md)).

## Threat model

Who can put text into a page or an export:

- **The author of an architecture document.** Usually the user's own agent, writing from the user's words. But documents also come from elsewhere: a repository the agent was asked to diagram, a requirements document the user uploaded, a colleague's file. Any text in them (titles, labels, sublabels, card items, decision records, trace notes, requirement values, child diagrams) is treated as untrusted, and so is a pinned brand URL (`brand: {url, sha256}`), which the command line fetches when the document is rendered (S-08).
- **Nobody else.** A rendered page is a static file with no server. It makes no network request of its own. Whoever can edit the HTML file itself can make it do anything; that is out of scope, as for any HTML file.

What must hold:

1. Authored text is shown as text: in the page, in a child diagram (level), and in every export. It never becomes markup, script, an image, a directive or a link with hidden text. (A bare http(s), www or e-mail address in a Markdown export may be shown as a link by renderers that autolink, GitHub among them; the visible text is the address itself.)
2. A child diagram opened from a page cannot read or change the page that opened it.
3. The command line writes only where it is told to, and never over a file it did not create unless told to.
4. The skill makes no network request the user did not ask for, except two that are documented and can each be turned off: the update notice and the re-check of a pinned brand (see "Network").

## Findings

| ID | Severity | Finding | Status |
|---|---|---|---|
| S-01 | **high** (release blocker) | **draw.io export: authored markup became live HTML in draw.io.** Every label cell is written with `html=1`, so draw.io reads the `value` attribute as HTML. Labels were escaped once, for the XML attribute only. A label `<img src=x onerror=...>` therefore reached draw.io as an image tag with an event handler; `<b>` as bold. Whether a handler runs depends on draw.io's own sanitiser, which this product cannot rely on. Affects `archi-made-easy export drawio` and the Handoff download in the page. | **Fixed.** Authored text in labels (components, sublabels, connections, boundaries) is escaped for HTML and then for the attribute. The exporter's own `<br>` and `<font>` remain the only tags. Regression tests: `test/workbench-export.test.mjs` ("draw.io shows markup in labels as text…"), `test/workbench-security.test.mjs` (every label of a hostile document parsed back as draw.io would; command-line export equal), and the browser test reads the Handoff download from the page. |
| S-02 | medium | **Design document (Markdown) export: authored text was inserted raw.** Markdown renderers (GitHub, wikis, many editors) pass inline HTML through or turn `[x](javascript:…)` and `![](https://…)` into links and remote images. A decision record or card item could add a tracking image or a link to a document a reviewer opens. | **Fixed.** Authored text is escaped for Markdown (backslash before `\` `` ` `` `*` `_` `[` `]` `<` `>` `\|`, line breaks folded). The exporter's own marks (the asterisk for assumed values) are kept. Tests: `test/workbench-security.test.mjs`. |
| S-03 | medium | **Mermaid export: authored text could end a statement or a code fence.** Labels were escaped for `"` only. Outside quotes (titles, sequence messages and notes) a `;` starts a new statement and `%%` a comment; a backtick run can close the Markdown fence around the diagram; `<` reached Mermaid's HTML labels. | **Fixed.** Authored text uses Mermaid entity codes (`#quot;` `#lt;` `#gt;` `#35;` `#96;`, and `#59;` `#37;` outside quotes). Headings use the Markdown escape. Tests: as S-02. The previous check of exports against the real Mermaid parser ([mermaid-parse-2026-11-10.md](acceptance/mermaid-parse-2026-11-10.md)) predates this change; see "Not verified". |
| S-04 | low | **Page script spelled a closing body tag** (D-035 in the visual QA register). Not exploitable on its own, but any tool that inserts into a page before the first closing body tag would have inserted inside a script. | **Fixed**, with a guard test (`test/workbench-levels.test.mjs`: the template holds each closing tag once). |
| S-05 | info | **No Content Security Policy in the page.** The page is a single offline file whose scripts and styles are inline, so a policy could only be `'unsafe-inline'`, which adds nothing. The page loads no remote resource. | Accepted; documented. |
| S-06 | low | **Development dependency with advisories: `fast-uri` 3.1.7 and 3.1.8** (four advisories, fixed in 3.1.9). Used only by `ajv` when the schema validators are generated; the generated validators import nothing from it, and it is not in the release archive. | **Fixed.** The existing override is raised to `^3.1.9` in both `package.json` files; both lockfiles resolve 3.1.9; `npm audit` reports 0 vulnerabilities in the repository and in `archi-made-easy/`. |
| S-08 | medium | **A pinned brand in a document makes the command line contact the host it names, with no way to refuse.** Rendering, validating or finalizing a document with `brand: {url, sha256}` re-fetches that URL to check the digest (inherited behaviour). Private and loopback addresses, credentials and non-standard ports are refused, so this is not a way into the local network, but a document from someone else learns the user's address and that the file was rendered, and its host name is resolved through DNS first. The threat model did not name the field. Found by the release-readiness audit. | **Fixed.** `ARCHI_MADE_EASY_BRAND_CAPTURE_DISABLED=1` refuses every remote brand request before any DNS lookup or socket; such a document fails with `brand/capture-unavailable` naming the switch. Documented in `references/brand-marks.md` and `references/installation.md`. Test: `test/brand-marks.test.mjs` (a local server counts requests: none while disabled, for `validate`, `render` and `brands capture`). The default is unchanged, because pinned brands are an inherited, documented feature. |
| S-09 | low | **`export --force` did not follow the command line's output contract.** It wrote through whatever was at the output path: a directory caused an unhandled exception instead of a diagnostic, and a link would have been followed to its target. Found by the release-readiness audit. | **Fixed.** The output must be absent or a regular file (checked with `lstat`, never followed); without `--force` the write is exclusive (`wx`), so a file created in between is not overwritten; a directory, link or special file is refused with `export/output-type`. Test: `test/workbench-export.test.mjs`: the directory case everywhere; the link case where the test can create a symbolic link (it needs a privilege on Windows, so on this machine that part reports itself as not exercised). The exclusive write between check and write is verified by reading the code. |
| S-10 | low | **Levels: a marker could also name the page's JSON data blocks**, not only the template's style and script, because both sides offer every large `<style>`/`<script>` body. Authored text cannot produce a raw marker (it is escaped in the child page, tested), so this only matters if a future renderer bug emitted raw markup; the child would then receive the parent's levels, workbench or evidence data. Found by the release-readiness audit. | **Accepted for 1.0.0** (defence in depth only, no path from authored text). Changing which blocks are shared changes the page script and every rendered page; scheduled for the next release with a test in `test/workbench-levels.test.mjs`. |
| S-11 | info | **Brand requests announced an inherited version number** in their user agent. | **Fixed.** The user agent carries the skill's own version from `package.json`; `test/brand-marks.test.mjs` reads it from the requests a local server receives. |
| S-12 | high | **Text exports: authored text could still add lines, directives and blocks** (found by the release-readiness audit, after S-01 to S-03). The escaping folded only LF line breaks, but CommonMark, Mermaid and Java's line reader (which Structurizr uses) also end a line at a lone carriage return. So a label holding a carriage return could add a `!script` or `!include` line to the Structurizr workspace, a statement (for example a `link` entry) to a Mermaid diagram, or a heading or code fence to the design document. In addition: Structurizr knows only the escape `\"`, so a value ending in a backslash escaped its own closing quote; Structurizr substitutes `${NAME}` with constants and environment variables; Mermaid reads `%%{init: …}%%` directives anywhere, also inside quoted labels; and an assumption that starts with `#`, `-`, `+` or `1.` became a block inside its list item. Rated high like S-01, because Structurizr runs `!script` and remote `!include` in its default unrestricted mode. | **Fixed.** Every line break (CR, LF, CRLF, vertical tab, form feed, NEL, U+2028, U+2029) is folded in all three text formats; Structurizr values keep backslashes literal and end with an invisible word joiner when they end in a backslash, and `${` is split by a word joiner; `%` is encoded as `#37;` in every Mermaid position; a list item escapes a leading block marker. Test: `test/workbench-security.test.mjs` ("line breaks, backslashes, substitutions and directives…"), which reads each export the way its consumer splits lines. Not verified in Structurizr or Mermaid themselves (see "Not verified"). |
| S-07 | medium (website only) | **The inherited website build (`website/`, Astro) has 7 advisories in its toolchain**: 5 high (`sharp`, `source-map-js`, `undici`, `vite` through `launch-editor`, `zod`) and 2 moderate. They concern the site's build and local development server. The website is not part of the skill or the release archive. | **Open.** Update the website's dependencies before the site is built and published; this review did not change them, to keep the site's own tests and build unchanged. |

How S-01 was confirmed: the label check in `test/workbench-security.test.mjs`, run against the draw.io exporter as committed in Phase 6 (`b2ef6c8`), finds 9 live tags in the labels of the hostile document (`<b>`, `<i>`, `<s>`…). Against the fixed exporter it finds none.

## What was checked and holds

**Data slots.** The workbench data, the levels data, the repository evidence and the translations are JSON inside `<script type="application/json">`, written by `serializeScriptJson`, which escapes `<`, `>` and `&`. Authored text cannot close the element. Tested with a document whose every text field holds `</script><script>…`, image, SVG and iframe payloads: the page has exactly as many script, iframe, image, anchor and SVG elements as the same document with harmless text; the artifact check still finds one diagram; the data read back equals the authored strings (`test/workbench-security.test.mjs`).

**The page never builds HTML from text.** `viewer/workbench.js` creates every element with `createElement` and sets text with `textContent`. It has no `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`, `new Function`, string timers or `javascript:` URLs; a test fails if one appears. In a real browser, the hostile document is taken through all nine modes, a scenario run, a trace and the level view: no element appears that the harmless document does not have, and nothing runs (`test/workbench-browser.test.mjs`, "hostile authored text stays text…").

**Levels (child diagrams).**
- A child page is rendered by the same renderer from the child document, so its authored text is escaped the same way, and it passes the same artifact checks before the parent is written.
- It is stored in the parent as JSON in the levels data slot. Its shared blocks are replaced by markers; the page restores them only from its own `<style>` and `<script>` elements, matched by length and hash. A marker that matches nothing leaves the level unopened with a message.
- It opens in an `iframe` with `sandbox="allow-scripts allow-downloads allow-modals"`: no `allow-same-origin`, so the child runs in an opaque origin and cannot read the parent's DOM, storage or cookies; no `allow-top-navigation` or `allow-popups`.
- The bridge carries one message, from child to parent, saying the child is ready (title, theme, component count). The parent accepts it only from that frame's window and with the random token it gave the child (`crypto.getRandomValues`, 128 bits). Nothing the child says is shown or acted on beyond marking the level ready.

**Exports from the page.** The Handoff downloads use the same exporter code as the command line (the generated engine copy, held equal by the parity test) and a `Blob` URL that is revoked after use. Image exports strip workbench overlays and `data-wb-*` attributes (`export-cleanup.js`, tested).

**Command line and paths.** The inherited path contract tests (`test/path-boundary-contract.test.mjs`, `test/output-path.test.mjs`, `test/meta-output-contract.test.mjs`) cover output paths, symlinks and aliases in `archi-made-easy/bin`, `delta`, `migrations`, `recipes`, `renderers` and `scripts` and in the repository's `scripts/`; new code there uses the shared `sameEntry` helper, which the contract test enforces. The installer (`archi-made-easy/install.mjs`) and `archi-made-easy/workbench/` are outside that test: the installer compares paths with its own rule (case folded on Windows and macOS only), and the workbench code handles no paths. `export` refuses to overwrite an existing file without `--force`, and never writes through a directory or a link even with it (S-09). Child diagrams are rendered into an owned temporary directory that is removed afterwards. Nesting is limited to three levels and four children per document.

**Installer.** New in Archi-Made-Easy (Phase 2), not inherited: it writes only to the chosen agent folders, refuses to replace or remove a folder that does not carry its marker, replaces a managed folder only with `--replace`, never follows or copies symbolic links, and supports `--dry-run` (`test/installer.test.mjs`: "an unmanaged existing folder is never modified", "managed installs replace only with --replace, and uninstall cleanly", "dry run writes nothing and unknown agents are rejected"). The Skills CLI path is covered by `test/skill-installation.test.mjs` (only the `archi-made-easy` skill is installed). The release-readiness audit found that targets were de-duplicated with a case-insensitive comparison on every system; it now folds case only on Windows and macOS, as its other comparisons do.

**Network.** The skill's code makes three kinds of request, all inherited: brand capture, for a URL the user names (`brands capture`) or a captured brand pinned in the document, which is fetched again at render time to check its digest (public addresses only, DNS pinned against rebinding, redirects and size limited, timeouts; turned off by `ARCHI_MADE_EASY_BRAND_CAPTURE_DISABLED=1`, S-08); the update check, notification only, which reads one fixed manifest URL on the project's GitHub Pages (`skill-release.json`; any other URL is rejected by `update-contract.mjs`), validates it strictly, never downloads or installs anything, and is turned off by `ARCHI_MADE_EASY_UPDATE_CHECK_DISABLED=1`; the local preview server on `127.0.0.1`. The workbench, the levels and the exporters make none. The acceptance runs check that a finished page loads no remote resource with the network switched off.

**Dependencies.** The skill has no runtime dependency: the release archive holds no `node_modules` and no lockfile. `npm audit` on 2026-11-10, after S-06: 0 vulnerabilities for the repository (17 development dependencies) and for `archi-made-easy/` (6). The website: see S-07.

## Not verified

- The exports were not opened in diagrams.net or Structurizr. Escaping is verified by parsing the output as those tools would, not in the tools.
- The Mermaid exports after the S-03 change were not re-parsed with the real Mermaid library (that check needs network access to load it).
- No fuzzing beyond the hostile document and the tests above.
- The inherited viewer modules (focus, route, lens, export, explainer reader) were reviewed for the paths the workbench uses, not line by line.
